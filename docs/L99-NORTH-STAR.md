## Scorecard

| Dimension | Grade | One-line verdict |
|---|---|---|
| Prompt & agent craft | B- | FrankX's 9-section agent family is genuinely strong; the most-used agent has a broken input path, and the hub uses an incompatible second convention |
| Loop architecture | C+ | A-grade doctrine (checkpoint capture, file contracts, human gates) — but re-ingest erases human decisions, the album contract is forked, and the learning loop is one sentence |
| Brand & naming | C | Coherent hub taxonomy buried under a four-way collision on Vibe OS — at the exact point money changes hands |
| Product & GTM | D+ | Real IP, pre-revenue music GTM: the quickstart 404s at step one, no paid SKU for the system itself, zero finished canon tracks to prove it |
| Tooling & data | C- | Doctrine is the healthiest layer; track data lives in 6+ shapes with 3 status vocabularies while the correct spine (track-state.json) already exists and is bypassed by its own dashboard |
| Commands & teams | C+ | Well-engineered registry/router undercut by name-colliding legacy agents, a front door not wired to its owner, and parallel writers with no locking |

**Overall: the doctrine is excellent, the drift is the disease.** Six of six audits found the same
failure class the ecosystem's excellence review predicted: descriptions diverging from reality
(spec vs schema, registry vs disk, page vs product, doc vs code). The cure is structural — single
sources of truth with validators — not more docs.

## The Ten Decisions

**D1 — Naming architecture (decided).** Masterbrand: **FrankX**. Public umbrella: **Music
Intelligence System** ("the Agentic Music Producer's OS" is its positioning tagline, not a second
name). **Vibe OS** = one thing only: the music state-change product (the paid Suno toolkit the
templates page already promises). **Album OS** retires as an outward name — publicly it is "the
album pipeline." **Arcanea** stays mythic-register only, with Solfeggio/frequency-canon language
confined to Arcanea label surfaces (per the existing Starlight brand-register rule) and hedged
research posture everywhere else. A `BRAND-MAP.md` table becomes the gate for any new name.

**D2 — One data spine (decided).** `track-state.json` keyed by `sunoId`, generated by the
already-built `build-track-state.mjs`, is the canonical track spine. suno-catalog.json = immutable
scrape feed; review-queue.json = event log; catalog.csv = release-ledger view; music-asset-registry
= deprecated/generated. Consumers (ops page, catalog page, agents) rewire to the spine. **No
Supabase, no Notion for track data** — no multi-user runtime exists to justify them; SQLite enters
only as a gitignored local index when 12k-track ingest actually begins.

**D3 — One album contract.** Reconcile `schemas/album.schema.json` with the Album OS spec (the
status-lifecycle enums are currently fully disjoint); `album-builder.mjs` validates whichever wins;
every downstream module codes against the schema, never the prose.

**D4 — Machine files never own human decisions.** Guardian confirmations and Frank-edits move to an
append-only decisions file the ingest planner never writes; a processed-sidecar ledger keyed by
sunoId makes re-runs skip instead of clobber. Track identity is sunoId everywhere; title-slug is a
display concern.

**D5 — The learning loop gets a real spec before code.** JSON Schemas for sidecar, take-log
(including kill/rework — negative data is what learning needs most), and a keep-rate ledger with a
deterministic aggregator; every prompt-pack cites which stats biased it. Post-release: a per-album
`retro.json` whose named reader is the next prompt-pack generator. Prediction accountability: store
predicted canon-fit per prompt, compare against Frank's keep verdicts.

**D6 — Break the canon-fit circularity.** Audio-measured features (librosa BPM/key, ffmpeg ebur128
LUFS) at intake override declared metadata; below the match threshold the tagger proposes **no**
Guardian (never alphabetically-first on zero signal). Local audio cache (gitignored) is the
substrate; Demucs stems and Matchering reference mastering follow per the excellence review.

**D7 — One prompt standard.** A single cross-repo `AGENT-STANDARD.md`: required sections,
frontmatter schema, output-contract minimum for any agent another agent may dispatch. Hub personas
that are deliberately portable say so in-file and define what changes when loaded as a subagent.
Shared CLI tools expose `--json`; consumers never scrape human stdout.

**D8 — Seven front doors.** `/create-music` (guided single track — wired to its actual owner),
`/album` (pipeline: ingest/sequence/status/release), `/music-triage` (catalog loop), `/music-song` +
`/music-release` (operated-label lifecycle), `/music-video --format` (absorbing mv-artwork/canvas/
render/visualizer as internal dispatch, old names as thin aliases), and the **swarm-orchestrator**
as meta-router for anything ambiguous. Everything else is internal. Parallel asset writers go
through an atomic-write helper or per-asset sidecars — never shared-column read-modify-write.

**D9 — The offer ladder (sequenced).** (1) Fix the funnel contradiction at /products/vibe-os —
*Frank decision required, see below*. (2) Ship a $27–37 **Vibe OS Producer Pack** via the proven
Gumroad pattern (Independent Producers ICP only). (3) Finish **one canon-compliant Arcanea track**
end-to-end — it is the case study everything else sells on. (4) Later: the album-pipeline workflow
priced in the existing $297–997 band; never invent SaaS subscription tiers for a product with no
backend. Fix the 404ing `pip install vibe-os-mcp` quickstart immediately; label the academy
financial projections as speculative.

**D10 — The excellence layer, per pipeline step.** Every step gets a gate, a reflection artifact,
and a named reader:

| Step | Gate (before) | Reflection artifact (after) | Who reads it |
|---|---|---|---|
| Ideation | last N retros + keep-rate stats loaded | prompt-pack cites its evidence | prompt-architect |
| Prompt creation | predicted canon-fit stored per entry | prediction vs keep verdict delta | eval harness (calibration) |
| Generation (Suno) | — (human taste) | take-log incl. kills/reworks | keep-rate aggregator |
| Intake | audio-measured features vs declared (mismatch flag) | processed ledger entry | re-run skip logic |
| Canon-tag | threshold: no Guardian below match floor | decisions file (human confirm) | album manifest |
| Master | Matchering reference + LUFS window | qc block in spine | release gate |
| Release | licensing + human gate | release ledger row | analytics import |
| Post-release | manual-export analytics import (no API exists) | `albums/<id>/retro.json` | next ideation cycle |
